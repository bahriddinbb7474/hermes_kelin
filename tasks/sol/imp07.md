## Что сделать
1. Отчёт админу 19:30 (Hermes cron, trusted job):
   - backend tool `get_admin_report_data` (если нет/неполон — довести):
     расходы дня/месяца по группам, статус плана, due обязательства,
     alert-события дня; только allowlisted поля, без интимных деталей;
   - job формирует отчёт ТОЛЬКО из tool-данных (цифры не из головы);
   - числа отчёта должны сходиться с БД (проверка в E2E: сверка с SQL).
2. Health-alerts:
   - датасет: ВСЕ фразы §10.2 + 3–5 перефразировок каждой (сам составь,
     узбекская кириллица + бытовые варианты);
   - LLM-путь: SOUL-инструкция — при жалобе на здоровье мягкий ответ Ойижон
     + вызов alert-tool (запись `alert_events` + немедленное уведомление
     админу через отдельный механизм доставки);
   - keyword-предохранитель: детерминированный слой (backend или plugin —
     реши сам, зафиксируй в DECISIONS), который ловит фразы §10.2 даже при
     «сломанном»/недоступном LLM-ответе;
   - AC жёсткий: recall уведомления админа = 100% на всём тест-сете;
     precision разумная (ложные срабатывания не спамят админа);
   - alert Ойижон не пугает: никакой медицинской паники, только мягкая
     поддержка и «сыну сообщила».
3. Отчёты по запросу админа («отчёт за сегодня/месяц») — через существующие
   tools, проверить работу с admin-аккаунта.
4. Тесты: offline — весь alert-датасет через keyword-слой (100%), report-данные
   на disposable PostgreSQL; live E2E — 19:30 отчёт (числа сверены с БД),
   2–3 живые alert-фразы с тест-Ойижон → уведомление тест-админу + запись
   `alert_events`, cleanup.
5. Deploy controlled (backup, rollback), mapping для нового job, evidence
   `docs/EVIDENCE_STAGE_7_<дата>.md`, README/ROADMAP статус.
