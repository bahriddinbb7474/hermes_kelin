# imp04 — отчёт

## Результат

Pre-code исследование Stage 5.4 завершено в публично доступной части и дополнено
обезличенными фактами из authenticated screenshot реального бытового аккаунта:
`docs/TZ/UTILITY_PORTAL_RESEARCH_5_4.md`.

Решение — **NO-GO для кода сейчас**. У HET есть официальный кабинет
`https://cabinet.het.uz/` и first-party JSON API
`https://cabinet-api.het.uz/`, но это не опубликованный API для сторонних
интеграций. Реалистичный кандидат — official frontend endpoint, только после
live-проверки с реальным аккаунтом и письменного разрешения/разъяснения HET.

## Подтверждено

- официальный владелец/URL и приложения;
- login+password, получение пароля по SMS, CAPTCHA и ONE.ID;
- 15-минутный idle timeout бытового кабинета;
- access/refresh token в frontend и Bearer auth;
- отдельные GET endpoints состояния счёта, показаний, расчётов и платежной
  истории;
- на реальном UI: предоплата в сумах, текущее/помесячное потребление в кВт·ч,
  начисление, тарифные ступени, вкладка показаний и история платежей;
- без токена read endpoints возвращают `401`;
- существующие payment/write функции перечислены и должны быть исключены;
- официальные кабинеты газа и воды существуют.

## Не подтверждено без аккаунта

- фактическая JSON schema и единицы;
- семантика prepaid/остатка/долга;
- точные billed/tariff/update-date поля;
- token TTL и рабочий refresh;
- устойчивость daily sync;
- разрешение HET на автоматизированное чтение.

## Безопасность

CAPTCHA не решалась, SMS/пароль не запрашивались, ONE.ID и платежи не
открывались. Полученный screenshot содержит персональные данные, поэтому сам
файл не добавлен в git; ФИО, полный лицевой счёт и платёжные строки в отчёт не
перенесены. Код, connector, migration 004 и VPS не затрагивались.

## Что требуется дальше

Нужны согласие владельца, тестовый доступ через безопасный secret channel,
письменный ответ HET об automation/rate limits и отдельное разрешение на
контролируемый read-only live test из Узбекистана. До этого Stage 5.4 остаётся
`PLANNED / NOT IMPLEMENTED`.
