# imp04 (Sol) — Pre-code gate Stage 5.4: исследование официального кабинета электрики

## Контекст
Hermes/Mariyam, Ташкент. Stage 5.4 (ТЗ «Этап 5.4», ~стр. 1497) — read-only
подключение коммунальных кабинетов, начиная с электричества. Это
ИССЛЕДОВАНИЕ, кода нет. По ТЗ приоритет: official API → official
export/endpoint → узкий детерминированный read-only connector.
Hermes-браузер с открытыми credentials запрещён.

## Что выяснить (по официальному кабинету электроснабжения для физлиц)
1. Точный официальный портал/приложение (URL), владелец (гос/поставщик).
2. Auth: логин (телефон/лицевой счёт?), пароль, SMS/2FA, CAPTCHA; стабильность
   сессии (сколько живёт токен/cookie, есть ли refresh).
3. Есть ли official API / личный кабинет с export (JSON/эндпоинты, которые
   использует их же frontend/мобильное приложение) — задокументировать
   фактические запросы/ответы (masked).
4. Доступные поля: показания, потребление текущее/прошлое + единицы, начислено
   UZS, предоплата/остаток/долг, тариф, дата обновления.
5. Какие write/payment действия существуют в кабинете (чтобы гарантированно
   их исключить); правила использования/ToS — законна ли автоматизация чтения.
6. Риски: частота изменений HTML/API, блокировки, rate limits.
7. Кратко: существуют ли аналогичные официальные кабинеты газа и воды
   (только факт наличия + URL, без глубокого исследования).

## Метод
Публичные источники + тестовый вход, если заказчик даст данные лицевого счёта
(спросить в чате; без данных — исследовать публично доступное и указать, что
требует проверки с реальным аккаунтом). Никаких попыток обхода
CAPTCHA/защит. Credentials в git/логи не попадают.
