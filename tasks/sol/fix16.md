## Задание

1. **Маршрут провайдеров.** Разобраться, откуда runtime берёт `base_url`
   (config.yaml / .env / auth.json) и почему при неизменном config.yaml маршрут
   ушёл на OpenRouter. Привести к целевой схеме из DECISIONS.md: primary — n1n
   (`https://api.n1n.ai/v1`, новый ключ заказчика; у него там скидка), fallback
   — та же модель через OpenRouter. Проверить новый ключ (`/v1/models` → 200) и
   живой ход через n1n по agent.log. `auth.json` привести в порядок (бэкап до
   правки), мусорный tmp-файл удалить. Итоговую схему отразить в снипетах
   `deploy/` и docs, commit+push. Если n1n снова нерабочий — НЕ импровизировать,
   оставить OpenRouter primary и написать в чат.
2. **Ротация routing при сбросе сессии.** Сверить живой `config.yaml` с
   `deploy/hermes_profile_mariyam_oyijon/config.skill-protect.snippet.yaml`
   (там `session_reset: daily, at_hour: 2, notify: false`; по fix02-luna на
   VPS мог остаться `at_hour: 4` — выровнять по снипету, 04:00 близко к
   бомдоду). Починить корень: после ежедневного сброса routing-записи Telegram
   должны указывать на новую сессию (или удаляться, чтобы gateway пересоздал).
   Реализация — профильным плагином/обёрткой, как `mariyam_outbound_filter`;
   Hermes core НЕ форкать. Тест-сторож на точку перехвата (урок fix02-luna:
   если Hermes переименует функцию, плагин молча отключится — тест должен
   упасть). Проверка: после ближайшего ночного сброса routing указывает на
   свежую сессию, диалог отвечает, история не тянется (in новой сессии — тысячи,
   не десятки тысяч).
3. **Malformed-ответ = ошибка провайдера.** Ответ с `finish_reason=length` при
   одновременно пустых content/reasoning/tool_calls и отсутствующем usage
   классифицировать как сбой провайдера: retry, затем fallback-провайдер — а не
   continuation. Тоже профильным плагином, не форком core. Итоговая ошибка,
   если все ретраи исчерпаны, должна идти через существующую маркировку
   `_ProviderFailureReply` (fix09-sol) — Ойижон видит узбекскую фразу, не
   английский текст. Тест-сторож на точку перехвата. Живая проверка: штатные
   ходы работают; сам malformed-сбой по требованию не воспроизвести — доказать
   тестами плагина и логикой, плюс наблюдение ближайших cron-слотов.
