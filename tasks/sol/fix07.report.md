# fix07 — замер резервной модели и fail-closed защита

Дата живой проверки: 2026-08-01. Канал: реальный Telegram Web, allowlisted тестовый аккаунт Ойижон. Основная модель — `gpt-5.6-luna` через n1n; сравнительный прогон — принудительно `deepseek/deepseek-chat` через OpenRouter. Перед каждым прогоном сессия сбрасывалась. После прогонов тестовые cron-job'ы и расходы удалены, тестовое обязательство отключено.

## 2. Модель и стоимость

Расчёт для 40 сообщений/день + 4 cron основан на уже измеренном профиле: 1,7 API-вызова на сообщение, около 13,8 тыс. токенов статического префикса на вызов, около 250 выходных токенов на вызов. Для сравнения использована консервативная месячная рамка **31 млн входных + 0,55 млн выходных токенов**; кэш-скидка не вычитается.

|---|---:|---:|---|
| [`deepseek/deepseek-chat`](https://openrouter.ai/deepseek/deepseek-chat/pricing) | $0.2002 / $0.8001 (минимальный активный провайдер; weighted average выше) | ≈ $6.65 | Дёшево, но live acceptance провален; primary запрещён. |
| [`google/gemini-2.5-flash-lite`](https://openrouter.ai/google/gemini-2.5-flash-lite/) | $0.10 / $0.40 | ≈ $3.32 | Самый дешёвый кандидат с tool calling; только после полного Telegram-прогона всех мутаций и узбекского языка. |
| [`google/gemini-2.5-flash`](https://openrouter.ai/google/gemini-2.5-flash) | $0.30 / $2.50 | ≈ $10.68 | Лучший следующий кандидат в бюджете $10–15, но его ещё нельзя назначать без такого же live acceptance. |

OpenRouter публикует поддержку tool calling через параметры `tools`/`tool_choice`; каталог можно фильтровать по `supported_parameters=tools` ([документация моделей](https://openrouter.ai/docs/guides/overview/models)). Фактически ключ текущего профиля проверен живым вызовом DeepSeek. Gemini перечислены как доступные OpenRouter модели, но доступ конкретного аккаунта и качество на этой схеме ещё нужно подтвердить живым платным прогоном.

**Вердикт:** на DeepSeek переезжать нельзя ни при каких эксплуатационных условиях текущей архитектуры. Практичный кандидат на отдельную приёмку — Gemini 2.5 Flash; Flash-Lite можно проверить следом как более дешёвый вариант, но заранее считать его безопасным нельзя.

## 3. Внедрённая страховка

Выбран минимальный fail-closed вариант: в profile-scoped конфиге `fallback_providers: []`. Основной `gpt-5.6-luna` восстановлен. Если он недоступен, Hermes не передаёт тот же полный набор мутирующих tools менее надёжной модели.

Почему не сделан «разговорный read-only fallback»: Hermes v0.18.x не имеет provider-scoped allowlist tools. Реализация потребовала бы нового backend/router/guard либо правил в SOUL — то есть второго «мозга» или изменений, прямо запрещённых границами fix07. Post-mutation readback тоже потребовал бы оркестрации в core/backend и не устранил бы утечки внутреннего текста. Fail-closed — единственная малая конфигурационная правка, которая гарантированно исключает ложное обещание о несделанной записи.

Коммит страховки: `cef842e` (`fix: fail closed when Mariyam primary model is unavailable`). SOUL, backend, migrations, guard-плагины, cron-расписание, `news_sources.json` и imp11 не менялись. Ключи `busy_ack_enabled`, `long_running_notifications`, `memory_notifications`, `tool_progress`, `session_reset daily 02:00` и `mariyam_outbound_filter` сохранены.

## 4. Что делать при недоступности основной модели

Рекомендация: отвечать честным коротким сообщением на узбекской кириллице без мутаций, например: «Ойижон, ҳозирча ёзиб қўя олмадим. Илтимос, бироздан кейин яна юборинг.» Это безопаснее молчания и несравнимо безопаснее ложного подтверждения.

Текущий Hermes после отключения fallback действительно не мутирует данные, но его встроенный текст пока непригоден для Ойижон: `⚠️ The model provider failed after retries. I kept raw provider details out of chat; check gateway logs for diagnostics.` Замена этой строки требует отдельного согласованного UX-изменения вне границ fix07; в этой задаче она намеренно не внесена.
