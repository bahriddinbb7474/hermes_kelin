# fix04 — отчёт deploy и live-приёмки

## Итог

Кандидат `SOUL.md` из commit `5aba37f` был штатно развёрнут на VPS и имел
требуемый нормализованный SHA-256
`5ca28f1dc4853bc5874b210b63003f35a56d947b64aab58c5c4b4f84febf402d`.

Live-приёмка остановлена на блокирующем кейсе 6: Мариям вышла за бытовую
сторону обычая и от себя описала религиозную часть обряда. По инструкции fix04
немедленно выполнен rollback **только SOUL**. Сейчас активен предыдущий SOUL с
SHA `f8e435f54026eeeecaf5eb4d29eeb22e871ceb55e4812fb6b14d78f55e791bc8`;
gateway `active`.

## Процедура deploy

1. До изменения проверены старый VPS SHA `f8e435…`, gateway `active`, оба ключа
   fix03 и наличие его rollback-файла.
2. Repo-файл передан как `/tmp/fix04-SOUL.md`; SHA временного файла до deploy —
   `5ca28f…`.
3. Предыдущий SOUL сохранён в приватный rollback-каталог:
   `~/.hermes/profiles/mariyam_oyijon/backups/fix04-20260731T181222Z/SOUL.md.before`,
   mode `0600`.
4. Остановлен только `hermes-gateway-mariyam_oyijon.service`; новый файл
   установлен как profile `SOUL.md`, mode `0444`.
5. Через штатный `SessionStore.reset_session()` точечно ротирована одна session
   private-mapped test-user. Один другой route не изменён; counters новой
   session = `0/0/0`.
6. Выполнен `hermes --profile mariyam_oyijon config check`, запущен только
   профильный gateway. После deploy: SHA `5ca28f…`, gateway `active`, один
   gateway process.

Дополнительный offline inspector из `/opt/hermes-mariyam` не запускался: среда
заблокировала исполнение непроверенного скрипта из отдельного private checkout.
Обязательная проверка фактического deployed SHA прошла.
