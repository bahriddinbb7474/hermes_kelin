# fix08 — узбекская ошибка и Luna-fallback через OpenRouter

Дата живой проверки: 2026-08-01, реальный Telegram Web, allowlisted тестовый аккаунт Ойижон. Основной рабочий маршрут после проверки: `provider: custom`, `model: gpt-5.6-luna` (n1n.ai). Единственный резерв: `openai/gpt-5.6-luna` через OpenRouter. Заказчик отдельно подтвердил передачу Telegram-сообщений и системного контекста OpenRouter при резервных вызовах.

## 1. Человеческая фраза вместо английской ошибки

Штатного config-key для текста ошибки в Hermes v0.18.x нет. `gateway/run.py::_sanitize_gateway_final_response` жёстко формирует четыре английские категории (общий отказ, auth, policy, rate limit), а существующий плагин оборачивал только `_prepare_gateway_status_message`.

Расширен существующий profile-scoped `mariyam_outbound_filter` 1.0.1: он по-прежнему удаляет некириллические status-сообщения, а теперь также in-process оборачивает `_sanitize_gateway_final_response`. Для human chat surface любой оставшийся final reply с латиницей заменяется на одну фразу; для `local`, `api_server`, `webhook`, `msgraph_webhook` оригинальная диагностика остаётся без изменений. Hermes core не менялся.

Дословный текст для Ойижон:

> Ойижон, ҳозир жавоб бера олмадим. Илтимос, бироздан кейин яна ёзинг.

Live positive control: при одновременно недоступном основном URL и временно пустой fallback-цепочке запрос `Салом, Мариям.` получил в Telegram ровно эту фразу — без английского и технических подробностей. После контроля fallback и основной URL сразу восстановлены.

## 4. Живая проверка fallback

Журнал на каждом сценарии фиксировал `provider=custom`, этот URL и `APIConnectionError`; при этом Telegram получал полноценный ответ. При единственной настроенной fallback-записи и подтверждённом доступе это доказывает обработку резервной Luna через OpenRouter. Временный systemd drop-in затем удалён, daemon перечитан, Gateway перезапущен и остался `active`.

## 6. Prompt caching — только оценка

К нашей OpenRouter-схеме caching технически применим: 13,8 тыс. стабильных токенов заметно выше минимальных 1 024 для OpenAI, а OpenAI caching автоматический. OpenRouter использует sticky routing и рекомендует стабильный prefix; для более надёжной привязки agentic turns можно передавать постоянный `session_id`/`prompt_cache_key`, затем измерять `prompt_tokens_details.cached_tokens` и `cache_discount` ([официальная документация](https://openrouter.ai/docs/guides/best-practices/prompt-caching)). Однако сейчас OpenRouter — редкий fallback, поэтому его кэш почти не уменьшит основной счёт n1n. Чтобы кэш реально помог рамке $10–15, пришлось бы перевести обычный трафик Luna на OpenRouter (или получить эквивалентный тариф кэша у n1n), обеспечить стабильный prefix/session key и подтвердить экономию по реальному usage. В fix08 ничего из этого не внедрялось.
