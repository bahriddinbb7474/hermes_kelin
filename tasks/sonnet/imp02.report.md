Заказчик прислал ответ бота на `Бу ой қанча харажат бўлди?` (аккаунт админа,
как и требовало задание). Фактический ответ:

```

Озиқ-овқат          | 888 278 сўм
```

Проверка по 4 пунктам:

1. Таблица с 4 колонками (`Режа`/`Қолгани`) — **FAIL**, только 2 колонки.
2. `Кийим-кечак` отдельной строкой — **PASS**.
3. Еда одной строкой `Озиқ-овқат` — **PASS**.
4. Дословная финальная фраза — **FAIL**, вместо неё
   `Энг кўп харажат озиқ-овқатга кетибди.`

**Разбор по логам `agent.log` сессии `20260803_220016_3b4ca444`** (не по
тексту ответа — по фактическим tool-call):

- `22:00:16` (**до** деплоя, старый SOUL) — тот же вопрос `Бу ой қанча харажат
  бўлди?`, вызван только `get_expense_report` (9210 chars). Это баг fix13.
- `22:25:22` — деплой SOUL `c63f0233` (fix13).
- `22:28:46` — кейс 1, без tool-call, PASS.
- `22:29:13`–`22:29:24` (кейс 3, «Ичимликлар...») — вызваны **оба**:
  `get_monthly_budget_status` (1524 chars, план не пуст) и
  `get_expense_report` (800 chars) — верно для `CATEGORY_DETAIL`.
- `22:29:33`–`22:29:44` (тот же вопрос из задания, **после** деплоя) — вызван
  только `get_expense_report` (9210 chars), `get_monthly_budget_status` НЕ
  вызывался.
- `22:32:16` (другой вопрос, «...режаси бн солиштиргинчи...») — снова верно
  вызван `get_monthly_budget_status`.

Итого: `get_monthly_budget_status` явно работает и план на август **есть**
(1524 байта, не пусто) — если бы модель использовала его для этого ответа,
колонки `Режа`/`Қолгани` были бы. Но ровно тот же вопрос был задан в этой же
сессии дважды — до и после деплоя, с одинаковым (неверным) выбором tool.
Правдоподобная причина — модель повторила свой прежний (додеплойный) выбор
инструмента по истории диалога того же turn, а не переоценила правило заново.
Это **не опровергает и не подтверждает** fix13 однозначно: нужен чистый
повторный вопрос — либо в новой сессии (после ночного `session_reset`),
либо другой формулировкой, без истории с прежним (додеплойным) ответом на
тот же текст.

Не чинил и не правил SOUL — фиксирую по границе задания.
