# imp11 — Общий отчёт за месяц приходит подгруппами вместо групп

## Что увидела Ойижон

2 августа она спросила, сколько потрачено за месяц, и получила таблицу из двух
колонок и **десяти сырых подгрупп**: Кийим-кечак, Гўшт, Тайёр овқат,
Сабзавотлар, Нон, Бошқа харажатлар, Уй-рўзғор, Дон ва ёрмалар, Ширинликлар,
Мевалар. Ни плана, ни остатка, и без финальной фразы.

Заказчик: «я ожидал другой отчёт — сначала по группам, потом спросит, хотите ли
подробно какую-то группу, потом отдельно покажет. Написал ужасно».

## Ожидание записано в SOUL дословно — это дефект, а не пожелание

§5.2, `GENERAL_FAMILY_REPORT`: таблица
`Харажат гуруҳи | Режа | Сарфлангани | Қолгани`, группы в тексте —
`food`/`food.*` → **`Озиқ-овқат` одной строкой**, `medicine` → `Дори-дармон`,
`utilities` → `Коммунал`, `home` → `Уй`, остальные → `Бошқа`; товарных строк
нет; завершать дословной фразой
`Ойижон, хоҳласангиз, бирор харажат гуруҳини батафсилроқ кўриб чиқамиз.
Маълумотлар тайёр.` Подробности по группе — только после явной просьбы
(`CATEGORY_DETAIL`).

Модель не выполнила ни одного из трёх требований.

## Причина, которую я нашёл до постановки задачи — проверь её, не принимай на веру

`backend/db.py`, `get_monthly_budget_status`, CTE `actual`. Свёртка подгрупп еды
в `food` срабатывает по условию:

```
WHEN t.category_code LIKE 'food.%'
     AND EXISTS (SELECT 1 FROM planned parent_plan
                 WHERE parent_plan.category_code = 'food')
THEN 'food'
```

То есть подгруппы сворачиваются, **только если в плане есть строка `food`**. В
плане Ойижон план задан по конкретным продуктам и подгруппам, строки `food` в
нём нет — свёртка не срабатывает, и tool возвращает десять отдельных строк.

Дальше срабатывает инвариант проекта: суммы модель берёт только из tool result
и складывать сама не имеет права. Значит **правило §5.2 сейчас физически
невыполнимо**: SOUL требует одной строки `Озиқ-овқат`, а backend такой строки не
отдаёт. Ругать модель не за что — она напечатала полученное.

Подтверди это фактическими данными профиля (что именно вернул tool на её
запрос), а не только чтением кода. Если причина окажется другой — веди по
фактам, а не по моей версии.

## Срочность

`fix02` добавил четыре подгруппы еды, и `fix12` их уже описал в SOUL. После
ближайшего deploy этот экран станет **не десять строк, а четырнадцать**. Пока
свёртка не починена, каждая новая подгруппа делает главный отчёт мамы хуже.

## Что сделать

1. **Починить свёртку в backend.** Общий отчёт должен приходить группами
   верхнего уровня независимо от того, как составлен план. Подгруппы —
   только там, где их действительно просят (`CATEGORY_DETAIL` по группе `food`).

   Как именно — решай сам, но обоснуй в отчёте. Развилка, которую надо пройти
   осознанно и описать: если у части подгрупп план задан, а у части нет, то
   свёрнутая строка `Озиқ-овқат` должна показывать план как сумму планов
   подгрупп — иначе `Режа` и `Қолгани` в главной таблице соврут. Соврать в
   деньгах нельзя: на этих цифрах мама принимает решения.

2. **Не ломать `CATEGORY_DETAIL`.** Просьба «покажи подробнее еду» обязана
   по-прежнему давать подгруппы и товарные строки. Проверь оба сценария.

3. **Не ломать `COMPARE_OR_TREND`** и `set_monthly_budget` — они ходят в те же
   данные.

4. **Финальная фраза.** Проверь, возвращается ли дословное завершение общего
   отчёта после починки. Если модель её опускает по другой причине — назови
   причину; правку SOUL не делай сам, дай формулировку для Terra отдельным
   блоком в отчёте.
