## Контекст

Sol задачей `tasks/sol/imp10.md` загрузил в профиль `mariyam_oyijon` анкету
семьи, регулярные обязательства и опорный бюджет августа/сентября 2026

Но две живые проверки провалились. У Sol закончился недельный лимит, задача
переходит к тебе. **Приоритет — часть A.**

Реальная Ойижон пока не подключена, тесты — на втором аккаунте заказчика.

## A. Мариям не помнит семью (блокирующее)

На вопрос `неваралар нечта?` Мариям ответила, что данных нет.

При этом по отчёту Sol:

- memory tool подтвердил запись семейного контекста;
- `USER.md` — 3 записи, 706/1 375 символов; `MEMORY.md` — 4 записи,
  1 404/2 200 символов;
- read-only проверка нашла семейный и финансовый маркеры **в frozen
  system-prompt snapshot**;
- session тестового пользователя точечно ротирована.

То есть данные лежат и в промпт попадают, а модель отвечает «не знаю».

Выяснить, почему, и починить. Возможные направления (не ограничивайся ими):

1. запись ушла не в тот scope — profile-level против user-level, `user_id`
   sentinel `0` против реального Telegram id тестового аккаунта;
2. frozen snapshot, в котором Sol видел маркеры, не тот, что реально уходит в
   запрос конкретной session (проверь фактический эффективный промпт этой
   session, а не эталонный — см. `tests/inspect_effective_prompt.py`);
3. память попала в секцию, которую модель считает служебной и игнорирует;
4. в SOUL нет указания искать личные сведения в памяти, и модель не
   догадывается туда смотреть;
5. toolset `memory` включён (он не в списке `disabled_toolsets`), но чтение
   могло не вызываться — проверь, обращается ли модель к памяти вообще.

Нужен точный ответ «почему», а не подбор. После починки — проверка вопросами:
`неваралар нечта?`, `катта невaрам неча ёшда?`, `келинимнинг исми нима?`
Ответы дословно в отчёт.

Если корень — в тексте SOUL, **сам его не правь**: сформулируй нужный пункт в
отчёте, правку сделает Terra. Всё остальное (профиль, конфиг, порядок записи,
scope) чини сам.

## B. Английская служебная строка на fallback-модели

При повторной семейной проверке, после переключения на fallback-модель, в чат
Ойижон попала англоязычная служебная строка. Персональные данные не утекли.

Задача `tasks/sol/fix03.md` уже закрыла busy-уведомления Hermes штатными
ключами профиля:

```yaml
display:
  memory_notifications: "off"
  tool_progress: false
  busy_ack_enabled: false
  long_running_notifications: false
```

Значит у fallback-пути (основная модель `gpt-5.6-luna` через n1n → fallback
deepseek) свой источник английского текста: уведомление о смене провайдера,
ошибка, retry-notice или что-то подобное.

Найти конкретный источник и закрыть его для профиля. Приоритет решений тот же,
что в `fix03`: штатный конфиг-ключ → минимальный profile-scoped фильтр
исходящих сообщений. **Hermes core не патчить и не форкать.** Если иначе никак
— описать вариант в отчёте и остановиться.

Инвариант: в чат Ойижон уходит только узбекская кириллица и только речь
Мариям. Она пожилая, по-английски не читает.

Зафиксировать регрессией по образцу существующих тестов в
`tests/test_mariyam_skill_protection.py` (там уже есть suppression-тесты с
positive control).
